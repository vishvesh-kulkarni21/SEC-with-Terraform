# How often do financial research agents get numbers wrong, and what reduces it?

**Measured on 8 companies, 90 ground-truth questions, 2,340 agent runs (~$16 of model calls).**

## Finding

**Grounding figures in structured filing data eliminates numeric errors. The choice of chunking strategy matters less than expected, and the "smart" table-preserving chunker was the worst.**

- An agent that reads figures through **XBRL tools made 0 numeric errors in 270 runs** (95% CI 0–1%). The same agent reading them from **retrieved 10-K text made 0.8–4.5% errors**, depending on the chunker.
- **Table-aware chunking had the highest error rate (4.5%) and fixed windows the lowest (0.8%).** Keeping tables intact turns every table into a self-contained, high-similarity match, including *look-alike tables*: other entities (equity-method investees, related-entity schedules) and near-synonym statements (comprehensive income for net income). The agent then copies a row whose label matches the question exactly. These errors are **systematic**: they recur on every repeat.
- **A stronger model doesn't reduce errors when retrieval is good, but it partly rescues bad retrieval.** On the best chunker, Gemini 2.5 Pro and Flash made the same number of errors (1.1% each) at 5.6× the cost per correct answer. On the companies where the table chunker failed (exploratory), Pro cut its error rate from 18.2% to 4.7%.
- **The critic caught 100% of planted errors (47/47) but only 0–50% of natural ones.** Planted errors are value-level (wrong number, scale or year). Real errors are mostly "right number, wrong row or entity", and those pass any check against the cited passage because the number really is there. **A planted-error catch rate overstates real-world protection.**

The practical recommendation: **take reported figures from structured data (XBRL tools), use retrieval for narrative context, and verify numbers against XBRL, not just against the cited passage.**

## Setup

| | |
|---|---|
| Companies (fixed before any run) | AAPL, MSFT, JNJ, WMT, KO, CAT, CVX, NKE: 8 sectors, 5 different fiscal year-ends |
| Questions | 6 metrics (revenue, net income, operating income, operating cash flow, total assets, equity) × 2 latest fiscal years = 90, each with an XBRL ground-truth value |
| Ground truth | XBRL "as most recently reported" (the latest 10-K's copy of each period) |
| Tolerance | display rounding or 0.5% relative, whichever is looser; a wrong fiscal year never matches |
| Conditions | text-only agent with one of 3 chunkers (fixed / section / table-aware), or an agent with XBRL tools |
| Models | Gemini 2.5 Flash (stage 1); Flash vs 2.5 Pro (stage 2, best chunker); temperature 0; 3 repeats |
| Critic | debate pipeline, one wrong number planted per side (value +7%, million↔billion, year shifted), 24 debates |

Everything above was frozen in `eval/eval_config.json` and `eval/companies.json` before the first experiment. Raw rows for every run are in `eval/results/*.jsonl`. Tables are regenerated by `python eval/run_eval.py report`.

## Results

### Stage 1: chunking strategy (Gemini 2.5 Flash, 270 runs per condition)

| condition | accuracy | alt. definition | numeric error rate (95% CI) | abstained | errors by distinct question | critic catches natural errors |
|---|---|---|---|---|---|---|
| **XBRL tools** | **95.9%** | 0.0% | **0.0%** (0–1%) | 4.1% | 0 / 90 | n/a |
| fixed | 93.3% | 4.4% | 0.8% (0–3%) | 1.5% | 2 / 90 | 1 of 2 |
| section | 91.1% | 3.7% | 2.7% (1–5%) | 2.6% | 5 / 90 | 1 of 7 |
| table-aware | 91.9% | 2.6% | 4.5% (3–8%) | 1.1% | 5 / 90 | 0 of 12 |

**Error taxonomy.** Every error made in text mode, classified:

| condition | wrong period | wrong line item / misread row | fabricated | wrong scale | stale / restated |
|---|---|---|---|---|---|
| fixed | 1 | 1 | 0 | 0 | 0 |
| section | 5 | 1 | 1 | 0 | 0 |
| table-aware | 0 | **12** | 0 | 0 | 0 |

- **Section-aware** chunks mostly produce **wrong-period** errors: the right table, the wrong column.
- **Table-aware** chunks produce only **wrong-line-item** errors, and all 12 come from look-alike tables: Coca-Cola's equity-method investees (6), a Chevron related-entity schedule (5), and Caterpillar's statement of comprehensive income, where "comprehensive income attributable to shareholders" was read as net income (1).
- **Scale errors never happened** in any condition: the agent always carried the table's stated unit through.

### Stage 2: model (fixed chunker, 270 runs per model)

| model | accuracy | numeric error rate | p50 latency | cost / correct answer |
|---|---|---|---|---|
| Gemini 2.5 Flash | 93.0% | 1.1% (0–3%) | 2.9 s | $0.0029 |
| Gemini 2.5 Pro | 95.6% | 1.1% (0–3%) | 9.9 s | $0.0161 |

Pro's higher accuracy comes from fewer abstentions and fewer alternative-definition answers, not from fewer numeric errors. Flash's 1.1% also independently replicates its Stage 1 result on the same chunker (0.8%).

### Interaction: chunker × model

- **Pre-registered grid (AAPL, JNJ, WMT):** 0 errors in every cell, so it's inconclusive. These companies have no look-alike tables, a floor effect.
- **Exploratory grid (KO, CVX), chosen after Stage 1 and therefore post-hoc:**

| chunker | Flash | Pro |
|---|---|---|
| fixed | 2.3% | 0.0% |
| section | 2.3% | 2.3% |
| table-aware | **18.2%** | **4.7%** |

The table-chunker failures replicated on fresh runs with Flash. **Pro mostly avoids them, so chunker and model interact.** Model strength matters most exactly where retrieval is misleading.

### Critic on planted errors (24 full debates, 47 planted errors)

| planted error | caught | caught by |
|---|---|---|
| value (+7%) | 16 / 16 | value mismatch against XBRL (16); LLM layer also flagged 7 |
| scale (million↔billion, ÷10) | 16 / 16 | value mismatch (16); LLM layer 12 |
| period (year shifted) | 15 / 15 | wrong-period check (15); LLM layer 11 |
| **total** | **47 / 47 (95% CI 92–100%)** | |

Of 283 draft claims, **40% failed first review**, 31% of them for claims the cited evidence didn't support (causes, forecasts, valuation calls without a price). After revision, 23 were removed and 259 kept. A debate takes about 3 minutes (p50) and costs about $0.11.

## What else the measurements showed

1. **About half the raw "errors" were definition disagreements, not hallucinations.** Before the taxonomy was applied, Stage 1 error rates were 5.3/6.5/7.1%. Reading every error showed answers like *Walmart total equity including noncontrolling interest* ($105,887M vs parent equity $99,617M) and *Chevron sales and other operating revenues* ($193,414M vs XBRL `Revenues` = total revenues and other income, $202,792M). Both readings are defensible. They're now reported as `alt_definition`, and the classifier bugs behind the mislabelling are documented in DECISIONS.md D42. **A single error rate would have overstated hallucination by 1.6–6.6×, depending on the chunker.**
2. **Models trust their own sense of "now" over tools.** Told `latest_fiscal_year: 2026`, the researcher still analysed Microsoft's FY2022–2023. Every number was correct *for those years*, so no value check could catch it. The fix is a policy in code: the orchestrator pins the fiscal years, and the critic rejects figures outside them.
3. **Models do arithmetic when allowed to.** The deployed researcher wrote "up 4.16 percentage points" by subtracting two tool outputs itself. It was fixed with a `change` tool plus a deterministic scan that flags any number in an answer that matches no evidence. Subtracting rounded displays can also be wrong on its own: 26.92 − 23.97 = 2.95, but the true difference is 2.94.

## Limitations

- **Small effective sample for the chunker comparison.** Repeats aren't independent (the errors cluster by question), and by distinct question the chunker gap is 2 vs 5 of 90. The robust result is XBRL tools vs text. The ordering between chunkers is suggestive.
- **One embedding model and a fixed top-k (5).** Hybrid (keyword + vector) search or reranking could change the table-chunker result, and adding context to table chunks is the obvious next experiment.
- **Question scope.** The questions are headline figures that exist in XBRL. Segment and product figures, which exist only in text, weren't scored numerically.
- **Company set.** 8 large US companies with no banks (their statements don't fit the metric set). The interaction result is exploratory.
- **Cost uses list prices** from the config and should be checked against current Vertex AI pricing.

## Reproduce

```bash
python eval/run_eval.py stage1                    # ~20 min, ~$3
python eval/run_eval.py stage2 --strategy fixed
python eval/run_eval.py grid
python eval/run_eval.py debate --strategy fixed

```

The EDGAR cache is a frozen snapshot, so ground truth and filing text don't change between runs.
